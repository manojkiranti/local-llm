Context for AI coding assistants working in this repo.

## What this is

`di-local-rag` is a FastAPI-based **Retrieval-Augmented Generation (RAG)** backend with **document-group scoping**. It ingests `.txt` / `.md` / `.pdf` / `.docx` documents, embeds them with `BAAI/bge-m3`, stores vectors in **Qdrant** and metadata in **PostgreSQL**, and answers questions through a local **Ollama** LLM (default `qwen2.5:latest`).

Tailored for English + Nepali content. Auto-detects Devanagari and converts Preeti-font text to UTF-8 via `npttf2utf`.

## Architecture notes (load-bearing)

- **Single Qdrant collection** (`docs_nic_multilingual` by default), partitioned by a `group_name` payload field with a keyword index — not separate collections per group.
- **Lazy initialisation** via `@lru_cache`: `get_settings`, `get_qdrant_client`, `get_retrieval_service`, `get_llm_service` are all process-level singletons. The embedding model is loaded once on first `RetrievalService` instantiation and reused for all encodes — do not re-instantiate it.
- **Lifespan** in `app/main.py` calls `init_db()` (SQLAlchemy `create_all`) and `ensure_collection_exists()` (creates the Qdrant collection + payload index for `group_name`). There's no migration tool — see "Schema changes" below.
- **Background tasks** for embedding use FastAPI's `BackgroundTasks` and an in-memory `_task_status` dict in `app/api/routes/documents.py`. State is lost on restart.
- **Chunk IDs are deterministic**: `uuid5(NAMESPACE_URL, f"{path}::{chunk_index}")`. Re-embedding the same file overwrites its existing points.
- **Devanagari detection** gates Preeti conversion — see `needs_preeti_conversion` in `services/embedding.py`. Don't run the mapper on text that's already Unicode.

## Group indexes (new)

A **group** is a named, described bucket of reference documents. The `description` is stored once and injected into the LLM prompt during `/verify` so the model knows the domain. Retrieval can be scoped to a group via:

- `POST /ask` body field `group_name`
- `GET /search` query param `group_name`
- `POST /groups/{name}/verify` — uploads a target document and returns a structured JSON report (`satisfied` / `missing` / `unclear` / `summary` / `reference_files`) generated by comparing the target against reference chunks pulled from the named group.

See `docs/GROUPS.md` for the user-facing walkthrough.

## Schema changes

`Base.metadata.create_all` only creates **new** tables — it does **not** ALTER existing ones. When adding a column to an existing table (e.g. `group_name` on `embedded_files`), apply the SQL manually on environments that already have data. The repo has no Alembic setup; this is intentional for now. If migrations become frequent, introduce Alembic before adding more drift.

## Conventions

- Type-annotate everything; the codebase uses `from __future__ import annotations` and SQLAlchemy 2.0 `Mapped[...]` columns.
- Pydantic v2 models live in `app/models/schemas.py`. Use `model_config = {"from_attributes": True}` for ORM serialisation.
- Routes return Pydantic response models via `response_model=` when shape matters; otherwise return a dict.
- Errors raise `HTTPException` with explicit `status_code` + `detail`. Don't catch and swallow.
- Logging via the module-level `logger = logging.getLogger(__name__)`. Use `logger.exception(...)` inside `except` blocks.
- Don't hardcode secrets or model names — add to `app/config.Settings` and pull via `get_settings()`.

## Local commands

```bash
# Run the app (requires Postgres + Qdrant + Ollama)
uvicorn app.main:app --reload

# Run everything in containers
docker compose up -d

# Pull the LLM after first launch
docker exec ollama ollama pull qwen2.5:latest

# Sanity-check Python compiles
python3 -m compileall -q app/
```

## Watch out for

- `EMBEDDING_DEVICE=cuda` in `.env` requires a GPU + matching torch wheels + `nvidia-container-toolkit` in Docker. Drop back to `cpu` if you don't have GPU on the host you're running on.
- The Qdrant payload index on `group_name` is created idempotently on startup (`_ensure_group_payload_index`). If you change the field name, also rename the constant `GROUP_PAYLOAD_FIELD` in `app/db/qdrant.py`.
- Re-uploading a file with the same name to `download/` and re-running `/documents/embed` will overwrite the previous vectors for that path because chunk IDs are derived from the path.
- The `verify` LLM call asks for JSON only. If the model drifts, `_normalize_verify_payload` is the safety net — it returns an empty report with the raw output in `summary` rather than 500ing.
